# 05. v2設計書(要求仕様v2対応)

要求仕様v2(決算スケジュール・PDF自動取得・PDFビューア・コメント/株価保存)を、
既存のKessan Board(M1: Vanilla JS + Chart.js + localStorage)の上に増築するための設計書。

---

## 1. アーキテクチャ判断

### 1.1 静的Webアプリを継続する

v2でもサーバー・DBは持たない(個人利用・ログイン不要のため)。ただし静的アプリには
**ブラウザのCORS制約**という構造的な限界があり、v2要求のうち以下が影響を受ける。

| 要求 | 制約 | 設計上の扱い |
|---|---|---|
| 決算スケジュール自動表示 | TDnet系API(webapi.yanoshin.jp等)はCORS許可があれば直接fetch可能。JPXの発表予定(Excel)はCORS不可 | ①TDnet APIをブラウザから直接fetch(過去分)。②到達不可・未来分は**CSV/JSONインポート**と**手動追加**で補完 |
| PDF自動取得 | TDnetのPDFホスト(release.tdnet.info)はCORSヘッダを返さないため、ブラウザからのfetchは原則失敗する | fetchを試行→失敗時は「取得失敗」ステータス+**新しいタブで開いて手動アップロード**への導線を常設。取得ボタン・ステータス管理は仕様どおり実装し、成功時は自動保存 |
| 時価総額 | 無料・CORS可の時価総額APIがない | スケジュールCSVインポートまたは銘柄編集での**手動スナップショット値**。帯フィルタはこの値で動作 |

**この設計の含意:** 「一括取得」ボタンは実装するが、実運用では取得失敗→手動アップロード
フォールバックが主経路になる可能性が高い。フォールバックのUXを一級市民として設計する
(失敗一覧からワンタップでリンクを開き、ドロップで該当銘柄・期に紐づく)。

### 1.2 データ格納

- **アプリ状態**: localStorage 単一キー `kessan-board-state-v1`(version=2 にインクリメント、
  マイグレーション関数で v1→v2 変換)
- **PDFバイナリ**: **IndexedDB**(`kessan-board-pdfs`)。PDFは1本数百KB〜数MBで
  localStorage(5MB)に入らないため。ステート側にはメタデータ(pdfId・ファイル名・取得元・取得日時)のみ持つ
- JSONエクスポートはステートのみ(PDFは含めない。PDFは再取得・再添付可能な派生物と位置づける)

### 1.3 ファイル構成

```
├── index.html
├── styles.css
├── app.js        # 状態管理・ルーティング・全画面描画
├── metrics.js    # 指標レジストリ(v2項目を追加)
├── parser.js     # 短信PDF抽出(サマリー+BS/CF/セグメント best-effort)
├── viewer.js     # PDFビューア(pdf.js canvas描画)
├── db.js         # IndexedDB(PDF blob格納)
├── vendor/chart.umd.js
├── vendor/pdf.min.js / pdf.worker.min.js
└── Docs/
```

## 2. §17「残る確認事項」への決定

| # | 論点 | 決定 | 理由 |
|---|---|---|---|
| 1 | 説明資料の取得タイミング | **取得できる場合のみ任意で紐づけ** | 説明資料は開示タイミング・有無が銘柄依存。短信を主とする優先度(§2.2)と整合 |
| 2 | 時価総額の時点 | **スケジュール取得(インポート)時点のスナップショット** | 自動更新手段がない。スナップショットで帯フィルタ用途には十分 |
| 3 | 株価入力 | **複数項目**(分析時・決算前・決算後・目標) | 16.4の株価反応メモを先取り。バリュエーション計算は「分析時株価」を使用 |
| 4 | PER | **実績PERと予想PERの両方** | 予想EPSは短信サマリーの通期予想から取得できる |
| 5 | コメント形式 | **自由記述+補助項目**(第一印象/良かった点/悪かった点/次回確認/投資判断/株価反応) | 仕様8.2のとおり。投資判断は選択式(16.3の9段階) |
| 6 | スケジュール一覧の株価・売買代金 | **対象外** | データソースがない |
| 7 | 抽出不可の項目 | **「—」表示+ツールチップで「未取得」明示** | 空欄と区別。フォーム上は空欄+ハイライト(M1と同じ) |

## 4. 画面構成

グローバルナビ(4タブ)+モーダル。

| タブ | 内容 |
|---|---|
| **銘柄** | v1ホーム(ポートフォリオ一覧)。銘柄タップ→分析メイン画面 |
| **スケジュール** | 決算スケジュール一覧(過去1週間/未来1ヶ月切替、時価総額帯ほかフィルタ、チェック、PDF取得) |
| **チェック銘柄** | チェック済み一覧+一括取得・再取得(12.2/13章) |
| **保存済み分析** | 全records横断の一覧+検索(14章) |

### 4.1 分析メイン画面(銘柄詳細を拡張)

```

│   各カード: YoY・QoQ・(該当すれば)予想比、良化↑/悪化↓                          │
├ タブ: [PL] [BS] [CF] [セグメント] [PDF]                                        │
```

### 4.2 PDF取り込みフロー

```
PDF入手(いずれか)
  A. 手動アップロード(分析画面 or 期次入力モーダル)
  B. スケジュール/チェック画面の「取得」ボタン(fetch試行→CORS失敗なら
     「タブで開く」+手動アップロード導線)
→ parser.js で種別判定(短信/説明資料)+FY/Q/コード判定
→ 短信なら数値抽出→入力フォームにプリフィル(M1フォーム再利用)
→ 確認・保存(抽出フィールドは既定ロック。「抽出値の編集を許可」トグルで解除可 = 仕様8.4)
→ PDF本体はIndexedDBへ、メタはrecord.docsへ
```

### 4.3 抽出仕様(parser.js)

- **サマリーページ(1〜2p)**: 03_仕様書§3.5のラベル辞書方式。v2で辞書に追加:
  経常利益/EPS(1株当たり四半期(当期)純利益)/純資産/現金同等物期末残高/投資CF/財務CF/
  配当(四半期別+年間予想)/通期予想EPS
- **BS詳細(本表ページ)**: `現金及び預金` `棚卸資産(商品及び製品等)` `受取手形、売掛金` `支払手形、買掛金`
  `短期借入金/長期借入金/社債`(合算→有利子負債)をラベルマッチ。**best-effort**(失敗しても空欄なだけ)
- **セグメント(注記ページ)**: 「セグメント情報」見出し以降の表から
  セグメント名+売上高+セグメント利益を行単位で抽出。**best-effort**
- 説明資料PDF: 数値抽出は行わない(レイアウト自由度が高すぎる)。閲覧・紐づけのみ(仕様§2.2の補足用途)
- FCF・利益率・YoY・進捗率・PER等は**抽出せず全て導出**(metrics.js。二重管理排除の方針を維持)

### 4.4 スケジュールのデータ入力経路

1. **TDnet API(任意)**: 設定のAPIベースURLへブラウザから直接fetch(過去1週間の開示一覧)。
   成功時は自動でschedule行を生成・更新(announced=true、PDF URL付き)
2. **CSVインポート**: `日付,コード,銘柄名,市場,業種,時価総額(百万円),決算期,四半期` 形式。
   JPXの発表予定リスト等を整形して取り込む用途(未来1ヶ月をカバー)
3. **手動追加**: モーダルで1行追加

## 5. バリュエーション計算(仕様9章)

株価は「分析時株価」を計算に使用。百万円と円の単位差に注意(株式数は株)。

| 指標 | 式 | 元データ欠落時 |
|---|---|---|
| 実績PER | 株価 ÷ EPS(TTM) | 「—」 |
| 予想PER | 株価 ÷ 予想EPS(通期) | 「—」 |
| PBR | 株価 ÷ BPS(自己資本÷株式数) | 「—」 |
| 配当利回り | 年間配当予想 ÷ 株価 | 「—」 |
| 時価総額 | 株価 × 株式数 | 「—」 |

## 6. テスト方針

- **Playwright E2E**を継続。外部APIはPlaywrightの`page.route`でモックし、
  スケジュール取得→チェック→PDF取得(成功/失敗両方)→分析→コメント/株価保存→一覧、を通しで検証
- **抽出テスト**: 決算短信サマリーを模したHTMLをChromiumの`page.pdf()`でPDF化した
  フィクスチャを使い、parser.jsの抽出結果を検証(実際の短信様式に準拠したラベル・配置)
- 実運用の短信PDFでの抽出率検証は、ユーザーの手元での初回アップロード時確認(04_運用ガイド)に委ねる
