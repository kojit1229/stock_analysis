# 01. 実装方針

## 1. 技術スタック

TaskChute Journal PWA で実証済みの構成をそのまま踏襲する。
「新しい技術を覚える・保守する」コストをゼロにし、既存ツールと運用感覚を共通化する。

| レイヤ | 採用 | 理由 |
|---|---|---|
| フロント | Vanilla JS + HTML + CSS(フレームワークなし) | 既存流儀。ビルド工程ゼロ、`npm run dev` 相当のローカルサーバだけで動く |
| グラフ | Chart.js(単一ファイルをリポジトリに同梱)【Q2決定済】 | コンボチャート(棒+折れ線)・ツールチップ・レスポンシブを自前SVGで書くと工数がグラフだけで膨らむ。同梱すればオフラインもGitHub Pagesも問題なし |
| PDF解析 | pdf.js(同梱)によるテキスト抽出+自前パターンマッチ【Q1決定済】 | 短信サマリーページからラベル+数値を抽出しフォームへプリフィル。ブラウザ内完結でサーバー不要 |
| データ永続化 | `localStorage`(単一キー・単一JSONツリー) | データ量試算: 30銘柄 × 40期 × 約20項目 ≒ 数百KB。localStorage上限(5MB)に対して余裕。IndexedDBは過剰 |
| バックアップ | JSONエクスポート / インポート(必須機能) | localStorage唯一の弱点(ブラウザデータ消去で消える)への保険。TaskChute Journalと同じUX |
| バックエンド / DB | **なし** | 個人利用・単一端末前提。クラウド同期は必要になった時点で後付け(JSONインポートが移行経路になる) |
| デプロイ | GitHub Pages(静的ホスティング) | 既存と同じ。push するだけ |
| オフライン | PWA(manifest + service worker) | 既存の `sw.js` / `manifest.webmanifest` の書式を流用。iPad「ホーム画面に追加」で利用 |

### リポジトリ構成(案)

既存の TaskChute Journal とは**別リポジトリ**(例: `kessan-board`)として作成する。
ファイル構成は既存と同型:

```
kessan-board/
├── index.html
├── styles.css
├── app.js              # 状態管理・画面描画
├── metrics.js          # 指標定義レジストリ(拡張ポイント、03_仕様書 §4)
├── parser.js           # 短信PDF抽出ロジック(ラベル辞書+数値パターン、03_仕様書 §3.5)
├── vendor/chart.min.js # 同梱グラフライブラリ
├── vendor/pdf.min.js   # 同梱PDF.js(+worker)
├── manifest.webmanifest
├── sw.js
└── Docs/
```

## 2. 基本設計判断(依頼書 1〜14 への回答サマリ)

詳細な根拠と対案は [02_質問リスト.md](02_質問リスト.md)、定義は [03_仕様書.md](03_仕様書.md) を参照。

| # | 項目 | 判断 |
|---|---|---|
| 1 | 入力形式 | 【Q1決定済】**PDFアップロード→自動抽出→確認・保存**を主経路とする。ただし短信レイアウト差異による抽出失敗リスクに備え、抽出結果は**必ず入力フォームにプリフィルして確認を挟む**2段構え。抽出できなかった欄だけ手で埋めればよく、失敗しても運用が止まらない(03_仕様書 §3.5) |
| 2 | データ蓄積 | localStorageで確定。直近8期を同一画面表示(便利)。CSV/JSONエクスポートは**必須**。編集は履歴テーブルの行タップ→同じ入力フォームを再利用 |
| 3 | 指標 | 入力は「短信サマリー1ページから転記できる生データ」に限定し、指標はすべて自動算出。全業種統一セット+将来テンプレート拡張。**前年同期比(YoY)は必須**、前期比(QoQ)は季節性ノイズが大きいため補助扱い |
| 4 | UI | 銘柄詳細=**一画面ダッシュボード**(KPIカード+チャート+テーブルを縦積み)。画面遷移は「ホーム(一覧)⇄銘柄詳細」の2階層のみ。グラフは棒+折れ線コンボ、数値比較テーブルあり |
| 5 | 複数企業 | ホーム=ポートフォリオ一覧(指標×銘柄のヒートマップ的テーブル)。検索・フィルタは銘柄数〜30想定のため名前絞り込み+タグ(保有/監視)のみ |
| 6 | 時系列 | 標準**8期(2年)**、ワンタップで12期/全期間切替。ズーム・範囲選択は実装しない(期数切替で足りる) → [Q3](02_質問リスト.md#q3) |
| 7 | 警告 | ルールベースの赤信号を自動検出(営業CF・利益率・自己資本比率・進捗率等、03_仕様書 §5)。業種平均比較は公的データソースがないためMVP外 |
| 8 | 株価 | 【Q4決定済】**手動入力(任意項目)**。入力すればPER/PBR/配当利回りを自動算出。株価APIは無料枠の日本株対応が不安定+CORS制約のためMVP外 |
| 9 | 技術 | 上記 §1 のとおり |
| 10 | ワークフロー | 次回決算予定日を銘柄ごとに手動設定→ホームに「入力待ち」表示。修正は上書き(履歴保持なし、エクスポートが実質バックアップ)。バッチ入力は不要(決算日は銘柄ごとに分散するため) |
| 11 | 出力 | CSV/JSONエクスポート+印刷用CSS(ブラウザの印刷→PDF保存で代替)。Excelグラフ付き出力はMVP外 |
| 12 | レイアウト | ダークモード標準対応(既存ツールとトーン統一)。iPad横持ちを第一ターゲット、PC/iPhoneにレスポンシブ対応。ショートカット: `←/→`銘柄切替、`n`新規入力、`e`エクスポート |
| 13 | 拡張性 | 指標を `metrics.js` のレジストリ(id・ラベル・算出式・書式・警告ルール)に一元化。指標追加=レジストリに1エントリ追加のみ。プラグイン機構は過剰なので不要 |
| 14 | 制約 | 想定30銘柄・10年(40期)保持・初期表示 < 1秒(静的ファイル+localStorage読込のみなので余裕) |

## 3. 機能リスト(優先度順)

### P0 — MVP(これだけで毎四半期の運用が回る)

1. 銘柄登録・編集・削除(コード、名称、セクタ、決算月、タグ)
2. 四半期データ入力フォーム(累計値入力 → 単四半期は自動算出【Q6決定済】)
   ※抽出失敗時のフォールバック・修正編集にも使う共通部品のため、PDFより先に作る
3. **決算短信PDFアップロード→自動抽出→フォームへプリフィル→確認・保存**【Q1決定済】
4. 銘柄詳細ダッシュボード
   - KPIカード(最新期の主要指標+YoY)
   - 推移チャート(売上・営業利益の棒+利益率の折れ線、8期)
   - 期次データテーブル(YoY色分け付き)
5. 入力済みデータの編集・削除(テーブル行タップ→フォーム再利用)
6. JSONエクスポート / インポート(バックアップ・復元)
7. ホーム画面: 銘柄一覧+最新期主要指標+「入力待ち」表示

### P1 — 初版リリースに含めたい

8. 赤信号の自動検出・バッジ表示(ホーム/詳細両方)
9. ポートフォリオ一覧のヒートマップ表示(指標×銘柄、YoY背景色)
10. 通期予想の入力と進捗率表示
11. CSVエクスポート(銘柄単位・全体)
12. ダークモード / PWA(オフライン・ホーム画面追加)
13. 次回決算予定日の管理と入力待ちアラート
14. パーサーのラベル辞書メンテUI(抽出に失敗した銘柄の別名ラベルを登録)

### P2 — 運用が安定してから

15. 株価手動入力+PER/PBR/配当利回り【Q4決定済】
16. 表示期数切替(8/12/全期間)、指標の重ね描き切替
17. 印刷用CSS(1銘柄1ページのレポートレイアウト)
18. キーボードショートカット

### MVP外(明示的にやらないこと)

- 株価のAPI自動取得
- 業種平均との自動比較(データソースなし)
- Excel(グラフ付き)出力
- クラウド同期・複数端末対応
- 修正履歴の保持(監査要件なし)

## 4. マイルストーン(目安)

| フェーズ | 内容 | 完了条件 |
|---|---|---|
| M1 | P0のうち手動フォーム+ダッシュボード | 手持ち銘柄1社×8期分を入力し、ダッシュボードが見られる |
| M2 | P0残り(PDF抽出) | 保有銘柄の実際の短信PDFで抽出→確認→保存が通る(抽出率は銘柄ごとに検証) |
| M3 | P1一式 | 全保有銘柄を登録し、四半期の運用サイクルを1回完走 |
| M4 | P2から必要と感じたものだけ | 2四半期運用後の振り返りで選定 |
