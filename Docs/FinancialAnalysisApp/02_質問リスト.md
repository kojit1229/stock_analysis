## Q1. 入力形式

**背景:** 決算短信の1ページ目(サマリー)には必要な数値がほぼ全て載っており、
入力項目を絞れば手動でも1銘柄2〜3分で完了する。一方PDF自動パースは、
発行体ごとのレイアウト差異・東証様式改定への追随が必要で、
「パース失敗の調査」が四半期のリズムを壊す最大リスクになる。
KにはPython製短信パーサーの経験があるため、パースは**アプリ外**に置く選択肢もある。

- **案A(推奨): 手動入力フォーム**
  実装: 低 / 運用負荷: 1銘柄2〜3分。前年同期値を並記した入力フォームで転記ミスも即気付ける
- **案B: 手動フォーム+スマート貼り付け(P2)**
  実装: 中(正規表現ベース)。短信サマリーのテキストをコピペ→数値を自動で欄に振り分け。
  失敗しても手動fallbackできるため低リスク。まずAで運用し、面倒に感じたら追加が現実的
- **案C: PDFアップロード自動パース(pdf.js)**
  実装: 高 / 保守: 継続的。ブラウザ内での表構造抽出は精度が安定しない
- **案D: 既存Pythonパーサー活用**
  手元のPythonで短信→JSON変換し、アプリのJSONインポートで取り込む。
  アプリ本体は汚さず自動化できる。B同様、後付け可能

→ **どれがKの運用リズムに合うか?(A単独で開始し、B/Dを後付けする段階案を推奨)**

> ✅ **決定(2026-07-02): 案C(PDFアップロード)を主経路に採用。**
> リスク緩和のため「自動抽出→フォームにプリフィル→確認→保存」の2段構えとし、
> 抽出できなかった欄のみ手動入力で補完する設計(03_仕様書 §3.5)。

## Q2. グラフの実装方式

**背景:** TaskChute Journal は依存ゼロだが、金融チャート(2軸コンボ、ツールチップ、
レスポンシブ)を自前SVGで書くとグラフだけで工数の大半を食う。

- **案A(推奨): Chart.js の単一ファイルをリポジトリに同梱**
  実装: 低。CDN非依存なのでオフライン・GitHub Pagesとも問題なし。依存は「同梱1ファイル」のみ
- **案B: 自前SVG描画で依存完全ゼロ**
  実装: 高。既存流儀と完全一致するが、ツールチップ・軸目盛り等を全部書くことになる

→ **「依存ゼロ」ポリシーをこのアプリでも厳守したいか?**

## Q3. 標準表示期数

**背景:** 8期(2年)は前年同期比が2巡見え、四半期トレンドの反転を掴むには十分。
12期(3年)はコロナ等のイベント跨ぎの確認に有効だが、iPad画面ではラベルが窮屈になる。

- **案A(推奨): 標準8期、ワンタップで12期/全期間に切替**
- **案B: 標準12期固定**

→ **普段の分析でまず見たいのは2年か3年か?**

## Q4. 株価・バリュエーション指標

**背景:** PER/PBRは「決算の質」ではなく「値段」の指標。決算入力時に株価を1つ
手入力するだけでPER/PBR/配当利回りは自動算出できるが、株価は日々動くため
「入力した時点のスナップショット」にしかならない点をどう捉えるか。

- **案A(推奨): 株価は任意の手動入力(P2)。入力があればPER/PBR/配当利回りを表示**
  決算発表翌日の株価を入れておくと「その決算をいくらで評価したか」の記録になる
- **案B: 株価・バリュエーション系は本アプリのスコープ外**
  決算の質の分析に純化。値段は証券アプリで見る
- **案C: 株価API連携(MVP外だが将来ロードマップに載せる)**

→ **このアプリに「値段」の軸を持ち込むか?**

## Q5. 想定銘柄数

  セクタ・市場フィルタ、ソート機能をP1に昇格させる必要あり

## Q6. 四半期データの持ち方(累計 vs 単四半期)【設計上の重要判断】

**背景:** 決算短信のPL/CFは**累計値**(第2四半期なら上期累計)で記載される。
単四半期の値は自分で差分計算しないと得られない。どちらを入力単位にするかで
入力体験とデータ整合性が変わる。

- **案A(推奨): 短信のまま累計値を入力 → 単四半期値はアプリが自動算出**
  転記ミスが起きない(短信の数字をそのまま打つだけ)。前Qのデータが未入力の期だけ
  単Q算出不能となるが、その場合は累計ベースで表示すればよい
- **案B: 単四半期値を入力**
  グラフはシンプルになるが、入力のたびに手元で引き算が必要=転記ミスの温床

→ **A前提で仕様書を書いているが、単Q入力の運用に慣れがあれば教えてほしい**

## Q7. 通期予想と進捗率

**背景:** 短信サマリーには通期業績予想が載っており、「累計÷通期予想=進捗率」は
四半期決算の良し悪しを最速で判断できる指標の一つ。ただし入力項目が3〜4個増える。

- **案A(推奨): 通期予想(売上・営業利益・純利益)を入力し、進捗率+予想修正の検出を表示(P1)**
- **案B: 通期予想は扱わない(実績のみに純化、入力最速)**

→ **進捗率をKの分析プロセスで使っているか?**

## Q8. 第一ターゲット端末

**背景:** レイアウトの最適化優先順位を決めたい。レスポンシブで全対応はするが、
「一番気持ちよく使える画面」をどれにするかで設計が変わる。

- **案A(推奨): iPad横持ち第一**(TaskChute Journalと同じ利用シーン想定)
  ダッシュボードは2カラム(チャート+テーブル)配置
- **案B: PCブラウザ第一**
  より広い一覧比較・複数チャート並列を優先
- **案C: iPhone第一**
  入力を外出先で済ませる運用。ダッシュボードは縦積み

→ **決算チェックを主にどの端末でやる想定か?**
